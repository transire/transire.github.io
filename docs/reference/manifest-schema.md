# Manifest Schema Reference

## Overview

The `transire_manifest.json` file is automatically generated by the `transire gen` command through static analysis of your Go code. It serves as the single source of truth for:

- HTTP routes and their handlers
- Queue handlers and message types
- Scheduled jobs and their timing
- Dependency injection intents
- Cloud permissions requirements
- Packaging metadata

**You should never edit this file manually.** It is regenerated every time you run `transire gen`.

## How the Manifest is Generated

The manifest is created through build-time static analysis:

1. **AST Parsing:** The CLI parses `package main` using Go's `go/ast` and `go/types` packages
2. **Call Site Discovery:** Finds all `app.GET/POST/RegisterQueue/RegisterScheduled` calls in `main()`
3. **Type Inference:** Extracts message types from queue handler signatures
4. **Validation:** Verifies handler signatures and detects conflicts
5. **Generation:** Writes `transire_manifest.json` to the project root

**Constraints (MVP):**
- All registrations must be in `func main()` of `package main`
- Handlers must be top-level functions (no closures or method values)
- Queue message types must be concrete types (no interfaces or type parameters)

## Top-Level Structure

```json
{
  "version": 1,
  "service": "orders",
  "runtime": "go",
  "routes": [...],
  "queues": [...],
  "schedules": [...],
  "intents": {...},
  "packaging": {...},
  "discovery_constraints": {...}
}
```

### version

**Type:** `int`
**Description:** Manifest schema version. Currently `1`.

### service

**Type:** `string`
**Description:** Service name from `transire.yaml`.

### runtime

**Type:** `string`
**Description:** Runtime language. Currently `"go"`.

### routes

**Type:** `array` of route objects
**Description:** All registered HTTP handlers.

See [HTTP Routes Section](#http-routes) for details.

### queues

**Type:** `array` of queue objects
**Description:** All registered queue handlers.

See [Queue Handlers Section](#queue-handlers) for details.

### schedules

**Type:** `array` of schedule objects
**Description:** All registered scheduled jobs.

See [Scheduled Jobs Section](#scheduled-jobs) for details.

### intents

**Type:** `object`
**Description:** Declared permissions intents for cloud resources.

See [Intents Section](#intents) for details.

### packaging

**Type:** `object`
**Description:** Deployment artifact metadata.

See [Packaging Section](#packaging) for details.

### discovery_constraints

**Type:** `object`
**Description:** Build-time discovery constraints and metadata.

See [Discovery Constraints Section](#discovery-constraints) for details.

## HTTP Routes

### Route Object

```json
{
  "method": "GET",
  "path": "/orders/{id}",
  "path_params": [
    {
      "name": "id",
      "greedy": false
    }
  ],
  "handler": "getOrder"
}
```

#### method

**Type:** `string`
**Valid values:** `GET`, `POST`, `PUT`, `PATCH`, `DELETE`
**Description:** HTTP method for this route.

#### path

**Type:** `string`
**Format:** Chi router syntax
**Description:** URL path pattern with parameters.

**Path Parameter Syntax:**
- `{name}`: Single segment parameter (matches until next `/`)
- `{name+}`: Greedy parameter (matches rest of path, must be last segment)

**Examples:**
```
/users/{id}           → matches /users/42
/files/{path+}        → matches /files/docs/readme.txt
/orders/{id}/items    → matches /orders/123/items
```

#### path_params

**Type:** `array` of parameter objects
**Description:** Extracted path parameters from the route.

**Parameter Object:**
```json
{
  "name": "id",
  "greedy": false
}
```

- `name`: Parameter name (extracted from `{name}` syntax)
- `greedy`: Whether parameter is greedy (`{name+}`)

**Validation:**
- Duplicate parameter names are rejected
- Greedy parameters must be the last segment
- Parameter names must be valid identifiers

#### handler

**Type:** `string`
**Description:** Handler function name from your code.

**Validation:**
- Must be a top-level function in `package main`
- Must have signature: `func(w http.ResponseWriter, r *http.Request)`

### Complete Routes Example

```json
{
  "routes": [
    {
      "method": "GET",
      "path": "/orders",
      "path_params": [],
      "handler": "listOrders"
    },
    {
      "method": "GET",
      "path": "/orders/{id}",
      "path_params": [
        {"name": "id", "greedy": false}
      ],
      "handler": "getOrder"
    },
    {
      "method": "POST",
      "path": "/orders",
      "path_params": [],
      "handler": "createOrder"
    },
    {
      "method": "PUT",
      "path": "/orders/{id}",
      "path_params": [
        {"name": "id", "greedy": false}
      ],
      "handler": "updateOrder"
    },
    {
      "method": "DELETE",
      "path": "/orders/{id}",
      "path_params": [
        {"name": "id", "greedy": false}
      ],
      "handler": "deleteOrder"
    },
    {
      "method": "GET",
      "path": "/files/{path+}",
      "path_params": [
        {"name": "path", "greedy": true}
      ],
      "handler": "serveFile"
    }
  ]
}
```

## Queue Handlers

### Queue Object

```json
{
  "key": "ProcessedOrder",
  "handler": "processedOrderBatch",
  "message_type": "github.com/acme/orders.ProcessedOrder",
  "serialization": "json",
  "max_batch_size": 10
}
```

#### key

**Type:** `string`
**Description:** Queue registration key used in `app.RegisterQueue("key", handler)` and `app.Enqueue(ctx, "key", msg)`.

**Resource naming:** Physical queue is named `${service}-${env}-queue-${key}`.

#### handler

**Type:** `string`
**Description:** Handler function name from your code.

**Validation:**
- Must be a top-level function in `package main`
- Must have signature: `func(ctx context.Context, msgs []T) error`

#### message_type

**Type:** `string`
**Format:** Fully qualified Go type name
**Description:** Message type extracted from handler signature's `[]T` parameter.

**Examples:**
```
github.com/acme/orders.ProcessedOrder
github.com/acme/orders.OrderRequest
main.PaymentEvent
```

**Type Safety:** Each enqueued message includes a `__type` field automatically. The consumer validates this matches the registered `message_type`. Mismatches move the message to DLQ with a logged error.

#### serialization

**Type:** `string`
**Valid values:** `json`
**Description:** Message serialization format. Currently only JSON is supported.

#### max_batch_size

**Type:** `int`
**Range:** 1 - 10
**Default:** From `transire.yaml` (default 10)
**Description:** Maximum messages per batch delivered to this handler.

### Complete Queues Example

```json
{
  "queues": [
    {
      "key": "ProcessedOrder",
      "handler": "processedOrderBatch",
      "message_type": "github.com/acme/orders.ProcessedOrder",
      "serialization": "json",
      "max_batch_size": 10
    },
    {
      "key": "EmailNotification",
      "handler": "sendEmailBatch",
      "message_type": "github.com/acme/orders.EmailNotification",
      "serialization": "json",
      "max_batch_size": 5
    },
    {
      "key": "OrderReport",
      "handler": "generateReportBatch",
      "message_type": "github.com/acme/orders.ReportRequest",
      "serialization": "json",
      "max_batch_size": 1
    }
  ]
}
```

## Scheduled Jobs

### Schedule Object

```json
{
  "spec": "@daily 09:00",
  "resolved": "cron(0 9 * * ? *)",
  "handler": "processOrders",
  "timezone": "America/New_York"
}
```

#### spec

**Type:** `string`
**Description:** Schedule specification as written in code (shorthand or cron expression).

**Shorthand Syntax:**
- `@hourly`: Every hour (rate-based)
- `@daily`: Every 24 hours (rate-based)
- `@daily HH:MM`: Daily at specific time (cron-based)
- `@daily HH:MM TZ`: Daily at specific time in timezone (cron-based)

**Pass-through:**
- `rate(1 hour)`: EventBridge rate expression
- `cron(0 12 * * ? *)`: EventBridge cron expression

#### resolved

**Type:** `string`
**Description:** Cloud provider schedule format after resolving shorthand.

**Resolution Rules:**
- `@hourly` → `rate(1 hour)`
- `@daily` → `rate(1 day)`
- `@daily HH:MM` → `cron(MM HH * * ? *)`
- Pass-through expressions are unchanged

#### handler

**Type:** `string`
**Description:** Handler function name from your code.

**Validation:**
- Must be a top-level function in `package main`
- Must have signature: `func(ctx context.Context) error`

#### timezone

**Type:** `string`
**Format:** IANA timezone name
**Default:** From `transire.yaml` (default `UTC`)
**Description:** Timezone for cron-based schedules.

**Usage:**
- Applied to cron schedules only (those with specific times)
- Rate schedules are timezone-agnostic
- Can be overridden inline in spec (`@daily 09:00 UTC`)

### Complete Schedules Example

```json
{
  "schedules": [
    {
      "spec": "@hourly",
      "resolved": "rate(1 hour)",
      "handler": "syncInventory",
      "timezone": "UTC"
    },
    {
      "spec": "@daily 09:00",
      "resolved": "cron(0 9 * * ? *)",
      "handler": "generateDailyReport",
      "timezone": "America/New_York"
    },
    {
      "spec": "@daily 02:00 UTC",
      "resolved": "cron(0 2 * * ? *)",
      "handler": "cleanupOldRecords",
      "timezone": "UTC"
    },
    {
      "spec": "cron(0 */4 * * ? *)",
      "resolved": "cron(0 */4 * * ? *)",
      "handler": "healthCheck",
      "timezone": "UTC"
    }
  ]
}
```

## Intents

The `intents` section declares what cloud resources and permissions your application needs. This is used to generate least-privilege IAM policies.

```json
{
  "intents": {
    "sqs": {
      "send": ["ProcessedOrder", "EmailNotification"],
      "consume": ["ProcessedOrder", "EmailNotification"]
    },
    "logs": true,
    "xray": false
  }
}
```

### sqs

**Type:** `object`
**Description:** SQS queue permissions.

```json
{
  "send": ["ProcessedOrder"],
  "consume": ["ProcessedOrder"]
}
```

- `send`: Queue keys the application can send messages to (via `app.Enqueue`)
- `consume`: Queue keys the application consumes from (via registered handlers)

**Generated Permissions:**
- `send` → `sqs:SendMessage` permission for specified queues
- `consume` → `sqs:ReceiveMessage`, `sqs:DeleteMessage`, `sqs:ChangeMessageVisibility` for specified queues

### logs

**Type:** `bool`
**Description:** Whether application writes to CloudWatch Logs.

**Generated Permissions:** `logs:CreateLogStream`, `logs:PutLogEvents`

### xray

**Type:** `bool`
**Description:** Whether application uses AWS X-Ray tracing.

**Generated Permissions:** `xray:PutTraceSegments`, `xray:PutTelemetryRecords`

### Complete Intents Example

```json
{
  "intents": {
    "sqs": {
      "send": [
        "ProcessedOrder",
        "EmailNotification",
        "OrderReport"
      ],
      "consume": [
        "ProcessedOrder",
        "EmailNotification"
      ]
    },
    "logs": true,
    "xray": true
  }
}
```

## Packaging

Metadata about deployment artifacts.

```json
{
  "packaging": {
    "runtime": "provided.al2023",
    "http_zip": "build/orders-dev-http.zip",
    "bootstrap": true
  }
}
```

### runtime

**Type:** `string`
**Description:** Lambda runtime identifier.

**Value:** `provided.al2023` (custom runtime with Amazon Linux 2023)

### http_zip

**Type:** `string`
**Description:** Path to HTTP Lambda deployment artifact.

**Format:** `build/${service}-${env}-http.zip`

### bootstrap

**Type:** `bool`
**Description:** Whether artifacts use `bootstrap` executable naming convention.

**Value:** `true` (custom runtimes require executable named `bootstrap`)

### Queue and Schedule Artifacts

Queue and schedule handler artifacts are generated separately:

**Queue:** `build/${service}-${env}-queue-${key}.zip`
**Schedule:** `build/${service}-${env}-scheduled-${name}.zip`

Each contains a `bootstrap` binary with `TRANSIRE_HANDLER` environment variable:
- Queue: `TRANSIRE_HANDLER=queue:ProcessedOrder`
- Schedule: `TRANSIRE_HANDLER=schedule:hourly`

## Discovery Constraints

Metadata about build-time discovery constraints.

```json
{
  "discovery_constraints": {
    "package": "main",
    "entrypoint": "main",
    "registrations_in_main_only": true
  }
}
```

### package

**Type:** `string`
**Description:** Package where handlers must be defined.

**Value:** `main` (all handlers must be in package main)

### entrypoint

**Type:** `string`
**Description:** Function where registrations must occur.

**Value:** `main` (all registrations must be in func main())

### registrations_in_main_only

**Type:** `bool`
**Description:** Whether registrations in other functions/packages are supported.

**Value:** `true` (MVP constraint: registrations only in func main())

## Validation Rules

The CLI validates the manifest during generation and rejects invalid configurations.

### Route Validation

**E1003: Duplicate route**
```
Error: duplicate route 'POST /orders'
Routes must have unique method + path combinations
```

**E1006: Duplicate path parameter**
```
Error: path '/orders/{id}/items/{id}' contains duplicate parameter 'id'
Each path parameter must have a unique name
```

**E1007: Invalid greedy parameter**
```
Error: greedy parameter '{path+}' must be the last segment
Found: /files/{path+}/info
```

### Queue Validation

**E1004: Duplicate queue key**
```
Error: duplicate queue key 'ProcessedOrder'
Each queue handler must have a unique registration key
```

**E1005: Unable to infer message type**
```
Error: unable to infer message type for queue 'ProcessedOrder'
Handler signature must be: func(ctx context.Context, msgs []T) error
where T is a concrete type (not interface or type parameter)
```

### Handler Validation

**E1001: Invalid handler**
```
Error: 'getOrder' is not a function
Handler must be a top-level function in package main
```

**E1002: Invalid signature**
```
Error: handler 'createOrder' has unsupported signature
Expected: func(w http.ResponseWriter, r *http.Request) for HTTP handlers
Found: func(w http.ResponseWriter, r *http.Request, ctx context.Context)
```

## Manifest Errors and Fixes

### Handler Not Found

**Error:**
```
Error [E1001]: handler 'getOrder' not found in package main
```

**Cause:** Handler function doesn't exist or isn't in package main

**Fix:**
```go
// Make sure handler is a top-level function in main.go
func getOrder(w http.ResponseWriter, r *http.Request) {
    // ...
}
```

### Invalid Handler Signature

**Error:**
```
Error [E1002]: handler 'processOrders' has invalid signature
Expected: func(ctx context.Context) error
Found: func() error
```

**Cause:** Handler doesn't match required signature

**Fix:**
```go
// Queue handlers must accept context and message slice
func processedOrderBatch(ctx context.Context, msgs []ProcessedOrder) error {
    // ...
}

// Scheduled handlers must accept context
func processOrders(ctx context.Context) error {
    // ...
}
```

### Duplicate Route

**Error:**
```
Error [E1003]: duplicate route 'GET /orders'
First defined at: main.go:45
Duplicate at: main.go:52
```

**Cause:** Same method + path registered multiple times

**Fix:** Remove duplicate registration or use different path/method

### Type Inference Failed

**Error:**
```
Error [E1005]: unable to infer message type for queue 'ProcessedOrder'
Handler: processedOrderBatch
Signature: func(ctx context.Context, msgs []interface{}) error
```

**Cause:** Message type is interface{}, type parameter, or complex type

**Fix:**
```go
// Use concrete type
type ProcessedOrder struct {
    OrderID string `json:"order_id"`
}

func processedOrderBatch(ctx context.Context, msgs []ProcessedOrder) error {
    // ...
}
```

## Working with the Manifest

### Viewing the Manifest

```bash
# Generate and view manifest
transire gen && cat transire_manifest.json | jq
```

### Validating the Manifest

```bash
# Validate without deploying
transire gen --validate
```

### Understanding Manifest Changes

```bash
# See what changed
git diff transire_manifest.json
```

**Tip:** Commit the manifest to version control. This makes deployment deterministic and allows code review of infrastructure changes.

### Troubleshooting

**Manifest not updated:**
- Run `transire gen` after code changes
- Check for syntax errors in your Go code
- Ensure all registrations are in `func main()`

**Wrong message type detected:**
- Verify handler signature matches `func(ctx context.Context, msgs []T) error`
- Use concrete types, not interfaces or type parameters
- Check import paths for type definitions

**Missing routes/queues/schedules:**
- Confirm registration calls are in `func main()` only
- Check that handlers are top-level functions
- Look for typos in handler names
