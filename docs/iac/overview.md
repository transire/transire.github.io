# OpenTofu Overview

## What is OpenTofu?

[OpenTofu](https://opentofu.org/) is an open-source Infrastructure as Code (IaC) tool that lets you define and manage cloud infrastructure using declarative configuration files. It's a community-driven fork of Terraform, fully compatible with Terraform configurations.

**Key features:**
- **Declarative syntax** - Describe what you want, not how to build it
- **Cloud-agnostic** - Works with AWS, GCP, Azure, and more
- **State management** - Tracks actual vs. desired infrastructure state
- **Plan before apply** - Preview changes before execution
- **Open source** - Community-governed, no vendor lock-in

## Why Transire Uses OpenTofu

Transire generates OpenTofu configurations automatically from your application code. This approach provides:

1. **Zero boilerplate** - Write Go code, get infrastructure for free
2. **Type safety** - Infrastructure matches your handlers exactly
3. **Consistency** - Same infrastructure pattern for every service
4. **Transparency** - Generated files are readable and modifiable
5. **Version control** - Infrastructure changes tracked alongside code

**You don't need to be an OpenTofu expert** - Transire handles the complexity. But understanding the basics helps when customizing or troubleshooting.

## How Transire Generates IaC

When you run `transire gen`, Transire analyzes your Go code and creates OpenTofu configurations:

```bash
# Generate manifest and OpenTofu configs
transire gen
```

**What gets generated:**

```
infra/
├── backend.tf              # Remote state configuration (S3 + DynamoDB)
├── api_gateway.tf          # HTTP API Gateway (v2)
├── lambdas/
│   ├── http.tf             # Single HTTP Lambda (all routes)
│   ├── queues.tf           # Queue consumer Lambdas + SQS + DLQ
│   └── scheduled.tf        # Scheduled Lambdas + EventBridge rules
├── iam.tf                  # IAM roles and least-privilege policies
├── outputs.tf              # API URL, queue ARNs, etc.
└── overrides/              # Your custom Tofu (not generated)
    └── custom_iac.tf       # VPC, custom policies, etc.
```

**Generation process:**

1. **AST analysis** - `transire gen` parses your Go code
2. **Manifest creation** - Extracts routes, queues, schedules
3. **OpenTofu generation** - Creates `.tf` files from manifest
4. **Validation** - Checks for conflicts, missing dependencies

## OpenTofu Workflow

### 1. Initialize

Download provider plugins and set up backend:

```bash
cd infra/
tofu init
```

**What this does:**
- Downloads AWS provider plugin
- Configures S3 backend for state storage
- Creates state lock table in DynamoDB

**Only run once per project** (or when adding new providers)

### 2. Plan

Preview infrastructure changes:

```bash
tofu plan
```

**Output shows:**
- Resources to be created (green `+`)
- Resources to be modified (yellow `~`)
- Resources to be destroyed (red `-`)

**Always run before apply** to avoid surprises.

### 3. Apply

Create or update infrastructure:

```bash
tofu apply
```

**You'll be prompted to confirm changes.** Review the plan carefully, then type `yes`.

**This deploys your application** - Lambda functions, API Gateway, queues, and all supporting infrastructure.

### 4. Destroy (Optional)

Tear down all infrastructure:

```bash
tofu destroy
```

⚠️ **Warning:** This deletes everything. Use with caution, especially in production.

## State Management Basics

OpenTofu tracks infrastructure in a **state file** - a JSON representation of your actual resources.

### Local State (Development)

By default, state is stored in `terraform.tfstate` in your `infra/` directory.

**Pros:** Simple for solo development
**Cons:** Not shareable, easily lost, no locking

### Remote State (Recommended)

Store state in S3 with DynamoDB locking:

```hcl
# infra/backend.tf (generated by Transire)
terraform {
  backend "s3" {
    bucket         = "transire-tf-state"
    key            = "orders/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "tf-locks"
    encrypt        = true
  }
}
```

**Pros:**
- Shared across team
- Encrypted at rest
- Concurrent access protection (locking)
- Versioned (S3 versioning)

**Setup:** Run `transire init --backend` to create S3 bucket and DynamoDB table.

### State Best Practices

1. **Never commit state files** - Add to `.gitignore`:
   ```gitignore
   # .gitignore
   infra/*.tfstate*
   infra/.terraform/
   ```

2. **Use remote state for teams** - Always use S3 backend for shared projects

3. **Enable S3 versioning** - Rollback to previous state if needed

4. **Lock state during operations** - DynamoDB prevents concurrent modifications

5. **Backup state regularly** - S3 provides automatic backups

## Generated Resource Overview

### HTTP Resources

**Single Lambda for all HTTP routes:**
- Runtime: `provided.al2023` (AWS Linux 2023)
- Architecture: ARM64 (configurable)
- Handler: `bootstrap` (Go binary)
- Routes through Chi router internally

**API Gateway HTTP API (v2):**
- Single `$default` route with catch-all integration
- All routing handled inside Lambda by Chi
- Automatic HTTPS endpoint
- Supports custom domains (via overrides)

### Queue Resources

**For each queue handler:**
- **SQS Queue** - Main message queue
- **DLQ** - Dead-letter queue for failed messages
- **Lambda Consumer** - Processes messages from queue
- **Event Source Mapping** - Connects SQS to Lambda
- **IAM Permissions** - Queue send/receive, Lambda invoke

**Example:** Queue `"OrderCreated"` generates:
- Queue: `orders-dev-order-created`
- DLQ: `orders-dev-order-created-dlq`
- Lambda: `orders-dev-queue-order-created`

### Scheduled Resources

**For each scheduled handler:**
- **EventBridge Rule** - Cron or rate expression
- **Lambda Target** - Function to invoke
- **IAM Permissions** - EventBridge → Lambda invoke

**Example:** Schedule `"@daily 09:00"` generates:
- Rule: `orders-dev-scheduled-daily`
- Lambda: `orders-dev-scheduled-daily`
- Schedule: `cron(0 9 * * ? *)` (9 AM UTC or configured timezone)

### IAM Resources

**Least-privilege policies for:**
- Lambda execution role
- CloudWatch Logs access
- SQS send/receive permissions
- X-Ray tracing (if enabled)

**Generated policies are minimal** - only permissions your app needs.

## Customizing Generated Infrastructure

Transire never overwrites files in `infra/overrides/`:

```hcl
# infra/overrides/custom_iac.tf

# Add custom IAM policy
resource "aws_iam_policy" "s3_access" {
  name        = "orders-s3-access"
  description = "Allow order service to access S3 buckets"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "s3:GetObject",
          "s3:PutObject"
        ]
        Resource = "arn:aws:s3:::orders-bucket/*"
      }
    ]
  })
}

# Attach to generated HTTP Lambda role
resource "aws_iam_role_policy_attachment" "http_s3" {
  role       = aws_iam_role.http_lambda.name  # References generated role
  policy_arn = aws_iam_policy.s3_access.arn
}

# Add VPC configuration
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true

  tags = {
    Name = "orders-vpc"
  }
}

# Update Lambda to use VPC
resource "aws_lambda_function" "http" {
  # ... other config from generated file

  vpc_config {
    subnet_ids         = aws_subnet.private[*].id
    security_group_ids = [aws_security_group.lambda.id]
  }
}
```

**Override patterns:**
- VPC and networking
- Custom IAM policies
- API Gateway authorizers
- CloudWatch alarms
- Custom domains (Route53)
- Additional AWS resources (RDS, ElastiCache, etc.)

## Local vs Cloud

### Local Development

When running `transire run` locally:
- **No OpenTofu needed** - Local emulator runs in-process
- **No AWS resources** - Everything in memory
- **Fast iteration** - Instant restarts

### Cloud Deployment

When deploying with `transire deploy`:
- **OpenTofu applies changes** - Creates/updates AWS resources
- **Real infrastructure** - Lambda, SQS, EventBridge, API Gateway
- **Production-ready** - Scales automatically, fully managed

**Best practice:** Develop locally, deploy to dev environment frequently, promote to production with CI/CD.

## Deployment Process

Transire abstracts OpenTofu commands behind `transire deploy`:

```bash
# Deploy to default environment (dev)
transire deploy

# Deploy to specific environment
transire deploy --env=prod
```

**What happens internally:**

1. **Generate manifest** - `transire gen` (if needed)
2. **Package Lambdas** - Build Go binaries, create zip files
3. **Generate OpenTofu** - Create/update `.tf` files
4. **Initialize** - `tofu init` (if needed)
5. **Apply** - `tofu apply --auto-approve`

**You can also run OpenTofu manually** for more control:

```bash
# Generate files
transire gen

# Manual OpenTofu workflow
cd infra/
tofu init
tofu plan
tofu apply
```

## Common OpenTofu Commands

### View Current State

```bash
tofu show
```

Shows all deployed resources and their current configuration.

### List Resources

```bash
tofu state list
```

Lists all resources managed by OpenTofu.

### View Specific Resource

```bash
tofu state show aws_lambda_function.http
```

Shows detailed configuration for a specific resource.

### Refresh State

```bash
tofu refresh
```

Updates state file to match actual infrastructure (useful if resources changed outside OpenTofu).

### Validate Configuration

```bash
tofu validate
```

Checks syntax and configuration validity without connecting to cloud provider.

### Format Files

```bash
tofu fmt
```

Automatically formats `.tf` files to canonical style.

## Troubleshooting

### "Error: Backend initialization required"

**Cause:** Backend not configured or changed

**Fix:**
```bash
cd infra/
tofu init
```

### "Error: State lock acquire failed"

**Cause:** Another operation is running, or previous operation crashed

**Fix (if no other operation running):**
```bash
tofu force-unlock <LOCK_ID>
```

⚠️ **Only force unlock if you're certain no other operation is in progress**

### "Error: Resource already exists"

**Cause:** Resource exists outside OpenTofu management

**Fix:** Import existing resource or delete it manually:
```bash
# Import
tofu import aws_sqs_queue.my_queue queue-url

# Or delete manually via AWS Console and retry
```

### Generated Files Out of Sync

**Cause:** Made changes to handlers but didn't regenerate

**Fix:**
```bash
# Regenerate manifest and OpenTofu configs
transire gen

# Review changes
cd infra/ && tofu plan

# Apply changes
tofu apply
```

## Security Considerations

### State File Security

State files contain sensitive data:
- Resource IDs
- Configuration values
- Sometimes secrets (avoid storing secrets in state)

**Best practices:**
1. Enable S3 encryption (done by `transire init --backend`)
2. Restrict S3 bucket access (IAM policies)
3. Enable S3 versioning for recovery
4. Use DynamoDB for state locking

### IAM Permissions

Generated IAM policies are least-privilege by default:
- Lambda execution role
- Service-specific permissions only
- No wildcard actions

**Add custom permissions in overrides**, not by modifying generated files.

### Secrets Management

⚠️ **Never store secrets in OpenTofu files or state**

**Instead:**
- Use AWS Secrets Manager or SSM Parameter Store
- Reference secrets by ARN in Lambda environment variables
- Grant Lambda IAM permissions to read secrets

Example:
```hcl
# infra/overrides/secrets.tf
resource "aws_secretsmanager_secret" "db_password" {
  name = "orders/db-password"
}

resource "aws_iam_policy" "secrets_access" {
  name = "orders-secrets-access"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "secretsmanager:GetSecretValue"
        ]
        Resource = aws_secretsmanager_secret.db_password.arn
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "http_secrets" {
  role       = aws_iam_role.http_lambda.name
  policy_arn = aws_iam_policy.secrets_access.arn
}
```
