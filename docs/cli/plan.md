# transire plan

## Overview

`transire plan` generates and displays a deployment plan showing what infrastructure resources will be created for your application. It's a **preview-only** command that doesn't make any changes to your cloud environment.

**Purpose:**
- Preview infrastructure before deployment
- Validate manifest and configuration
- Understand what resources will be created
- Estimate costs and resource requirements
- Review deployment plan in human-readable or JSON format

## Usage

### Generate Plan for Default Environment

```bash
transire plan
```

Generates a plan for the first environment in `transire.yaml` (usually `dev`).

### Generate Plan for Specific Environment

```bash
transire plan --environment prod
```

Generates a plan for a specific environment.

### JSON Output

```bash
transire plan --output json
```

Outputs the plan in machine-readable JSON format (useful for CI/CD integration).

## Prerequisites

### 1. Workspace Initialized

Initialize your Transire workspace:

```bash
transire init
```

This creates the `.transire/` directory and `transire.yaml` configuration file.

### 2. Manifest Generated

Generate the application manifest from your Go code:

```bash
transire gen
```

This analyzes your code and creates `.transire/manifest.json` with all routes, queues, and schedules.

## What It Does

When you run `transire plan`, the CLI:

### 1. Loads Configuration

Reads `transire.yaml` to get deployment settings:

```yaml
service: orders-api
cloud: aws
iac: opentofu

deploy:
  architecture: arm64
  memory_mb: 256
  timeout_seconds: 30

queues:
  visibility_timeout_seconds: 30
  max_receive_count: 3
```

### 2. Loads Manifest

Reads `.transire/manifest.json` generated by `transire gen`:

```json
{
  "version": 1,
  "service": "orders-api",
  "routes": [
    {"method": "GET", "path": "/orders", "handler": "listOrders"},
    {"method": "POST", "path": "/orders", "handler": "createOrder"}
  ],
  "queues": [
    {"key": "fulfill-orders", "message_type": "Order", "handler": "fulfillOrders"}
  ],
  "schedules": [
    {"key": "daily-report", "schedule": "@daily 09:00", "handler": "generateReport"}
  ]
}
```

### 3. Generates Deployment Plan

Analyzes the manifest and configuration to determine what infrastructure will be created:

- **HTTP routes** → API Gateway + Lambda functions
- **Queue handlers** → SQS queues + DLQs + Lambda functions
- **Scheduled jobs** → EventBridge rules + Lambda functions
- **IAM roles and policies** → Least-privilege access

### 4. Displays Plan

Shows the plan in either human-readable text format (default) or JSON format.

## Use Cases

### Pre-Deployment Review

Review infrastructure before deploying:

```bash
# Generate plan
transire plan

# Review the output
# Check resource names, configurations, costs

# Deploy if satisfied
transire deploy
```

### CI/CD Integration

Use JSON output for automated checks:

```bash
# Generate JSON plan
transire plan --output json > plan.json

# Parse and validate
cat plan.json | jq '.resources.lambdas | length'
# Output: 3

# Check resource naming
cat plan.json | jq '.resources.lambdas[].name'
# Output:
# "orders-api-dev-http"
# "orders-api-dev-queue-fulfill-orders"
# "orders-api-dev-scheduled-daily-report"
```

### Multi-Environment Comparison

Compare plans across environments:

```bash
# Dev environment
transire plan --environment dev --output json > plan-dev.json

# Prod environment
transire plan --environment prod --output json > plan-prod.json

# Compare
diff <(jq -S . plan-dev.json) <(jq -S . plan-prod.json)
```

### Cost Estimation

Review resource specifications to estimate costs:

```bash
transire plan --output json | jq '.resources.lambdas[] | {name, memory_mb, architecture}'
```

Example output:
```json
{
  "name": "orders-api-dev-http",
  "memory_mb": 256,
  "architecture": "arm64"
}
```

Use this information with [AWS Lambda Pricing](https://aws.amazon.com/lambda/pricing/) to estimate costs.

## Command-Line Options

### `--environment` / `-e` (default: dev)

```bash
transire plan --environment prod
transire plan -e staging
```

Specify which environment to plan for. Must match an environment defined in `transire.yaml`.

### `--output` / `-o` (default: text)

```bash
transire plan --output json
transire plan -o json
```

Output format:
- `text`: Human-readable format (default)
- `json`: Machine-readable JSON format

## Planning vs Deployment

### `transire plan`

- **Purpose:** Preview only
- **What it does:** Shows what will be created
- **Safe:** No changes to cloud resources
- **Use when:** Reviewing infrastructure, CI/CD checks, cost estimation

### `transire deploy`

- **Purpose:** Create/update infrastructure
- **What it does:** Actually deploys to cloud
- **Modifies:** Creates real cloud resources
- **Use when:** Ready to deploy

**Recommended workflow:**

```bash
# 1. Generate manifest
transire gen

# 2. Review plan
transire plan

# 3. Deploy if satisfied
transire deploy
```

## Environment-Specific Plans

Configure multiple environments in `transire.yaml`:

```yaml
service: orders-api

env:
  - name: dev
    workspace: dev
    variables:
      LOG_LEVEL: debug

  - name: staging
    workspace: staging
    variables:
      LOG_LEVEL: info

  - name: prod
    workspace: prod
    variables:
      LOG_LEVEL: warn
```

Generate plans for each environment:

```bash
# Development
transire plan --environment dev

# Staging
transire plan --environment staging

# Production
transire plan --environment prod
```

Resource names are automatically namespaced by environment:
- Dev: `orders-api-dev-http`, `orders-api-dev-fulfill-orders`
- Prod: `orders-api-prod-http`, `orders-api-prod-fulfill-orders`

## Troubleshooting

### "Workspace not initialized"

**Problem:** `.transire/` directory not found

**Solution:** Initialize workspace first:

```bash
transire init
transire plan
```

### "Manifest file not found"

**Problem:** `.transire/manifest.json` doesn't exist

**Solution:** Generate manifest first:

```bash
transire gen
transire plan
```

### "Failed to load configuration"

**Problem:** `transire.yaml` is missing or invalid

**Solution:** Check configuration file:

```bash
# Validate syntax
transire gen  # Will validate config as part of generation

# Or recreate default config
transire init --force
```

### "Invalid environment"

**Problem:** Specified environment doesn't exist in `transire.yaml`

**Solution:** Check available environments:

```bash
# View config
cat transire.yaml | grep -A 5 "env:"

# Use valid environment name
transire plan --environment dev
```

## Best Practices

### Always Plan Before Deploy

Make planning part of your deployment workflow:

```bash
# Good practice
transire gen
transire plan
transire deploy

# Or combined
transire gen && transire plan && transire deploy
```

### Use JSON Output in CI/CD

Parse JSON output for automated validation:

```yaml
# GitHub Actions example
- name: Generate deployment plan
  run: transire plan --output json > plan.json

- name: Validate plan
  run: |
    # Check Lambda count
    count=$(jq '.resources.lambdas | length' plan.json)
    if [ $count -ne 3 ]; then
      echo "Expected 3 Lambda functions, got $count"
      exit 1
    fi

- name: Check resource names
  run: |
    # Ensure all resources have correct environment prefix
    jq -r '.resources.lambdas[].name' plan.json | grep -q "^orders-api-dev-"
```

### Review Plans for Production

Extra scrutiny for production deployments:

```bash
# Generate production plan
transire plan --environment prod > plan-prod.txt

# Review carefully
cat plan-prod.txt

# Check for unexpected changes
git diff --no-index plan-dev.txt plan-prod.txt

# Deploy only after approval
transire deploy --environment prod
```

### Save Plans for Audit Trail

Keep plans for change tracking:

```bash
# Create plans directory
mkdir -p plans

# Save timestamped plan
timestamp=$(date +%Y%m%d-%H%M%S)
transire plan --environment prod --output json > plans/plan-prod-$timestamp.json

# Commit to version control
git add plans/
git commit -m "Add deployment plan for prod"
```

## Integration Examples

### Shell Script

```bash
#!/bin/bash
set -e

ENV=${1:-dev}

echo "Generating deployment plan for $ENV..."
transire plan --environment $ENV --output json > plan.json

echo "Plan summary:"
echo "  Lambdas: $(jq '.resources.lambdas | length' plan.json)"
echo "  Queues: $(jq '.resources.queues | length' plan.json)"
echo "  Schedules: $(jq '.resources.schedules | length' plan.json)"

echo "Full plan saved to plan.json"
```

### GitHub Actions

```yaml
name: Preview Deployment

on:
  pull_request:
    paths:
      - '**.go'
      - 'transire.yaml'

jobs:
  plan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Go
        uses: actions/setup-go@v4
        with:
          go-version: '1.22'

      - name: Install Transire
        run: |
          curl -sSL https://get.transire.dev | sh
          echo "$HOME/.transire/bin" >> $GITHUB_PATH

      - name: Generate manifest
        run: transire gen

      - name: Generate plan
        run: transire plan --output json > plan.json

      - name: Comment plan on PR
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const plan = JSON.parse(fs.readFileSync('plan.json', 'utf8'));

            const body = `## Deployment Plan

            **Service:** ${plan.service}
            **Environment:** ${plan.environment}

            ### Resources
            - Lambda Functions: ${plan.resources.lambdas.length}
            - SQS Queues: ${plan.resources.queues.length}
            - EventBridge Schedules: ${plan.resources.schedules.length}
            - IAM Roles: ${plan.resources.iam_roles.length}

            <details>
            <summary>Full Plan</summary>

            \`\`\`json
            ${JSON.stringify(plan, null, 2)}
            \`\`\`
            </details>
            `;

            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: body
            });
```
